## 3. Choices the main assistant made while writing the OpenAPI file and the notes

- Wrote the plan file first, then the notes, the OpenAPI file and the brief, in one pass, and ran the final `grillz` review after the files existed. The change order applies to later changes.
- OpenAPI: one example per status; `HEAD` operations for the operational endpoints; `/metrics` marked optional; `type: 'null'` inside `oneOf` for `country`; `invalid_params` only on the 422 schema (through `allOf`); `warnings.code` an open string, not an enum; a problem `type` as a URI.
- OpenAPI: after the second review, removed the type, length and format constraints on `session_id` and `requested_at` from the request schema and described the limits in text; recorded this as G47. This was not a decision of mine.
- Notes: statuses A (approved, with a question ID) and P (proposed); every P item has a G entry; an appendix with the question and answer log so each approval has a source in the repo.
- Notes: marked the shared loopback/link-local sentence as approved, because it was in my E2a answer; kept the other `detail` texts as proposed.
- Notes: left the ISO check date as a visible placeholder (G1).
- Notes: dropped `database_reloads_total` from `/metrics` (G46) because the reload package has no observer hook; added G45 (no socket in tests), G47 and G39 to G44 myself.
- Manifest and Compose: replaced the placeholder string with an empty, commented `DATABASE_SANITY_CHECKS`, because a malformed value is a configuration error and would stop startup.
- Brief: numbered the rules R1 to R42, each citing a notes ID; re-cited five rules after the review.

## 4. Things the AI got wrong and I corrected

- The designer assumed D meant design/deployment and J meant the update job: replaced by my lettering.
- The designer assumed the "agent brief" was `CLAUDE.md`: "Agent brief is not CLAUDE.md."
- The designer planned to fetch the test database as an option: "Do not fetch it."
- The designer proposed extra reason codes (`private_address`, `loopback_address`, `reserved_address`, `not_in_database`): replaced by the four codes.
- The designer proposed `errors` items with codes, `malformed-json`, `service-unavailable` and a `not-found` type: replaced by `invalid_params` with `{pointer, reason}` and my seven types.
- The designer proposed a 1 MiB body limit: replaced by 16384 bytes.
- The designer's first plan conflicted with several of my decisions. My words: "Four of your proposals conflict with my decisions, so please correct them:" (I listed five items: the empty list, the statuses, the reload, the scope and cut order, the Go version and module path.) And: "Two of your "proposed" items are already decided:" (the `/version` shape and the panic log.) And the general rule: "For everything I already answered, use my answers. Please do not propose new ones."
- The designer's first plan also had a sanity default pair, startup failing until a placeholder was filled in, and gRPC as an optional build step. These were corrected in the reload, scope and sanity decisions above. The final approval also removed the startup failure: "the sanity-lookups setting must not make startup fail."
- Delivery problem, caught by the main assistant, not by me: the first revised plan was written before my corrections reached the designer, so it still had the old statuses and the old cut order. The assistant did not save it, and waited for the corrected plan.
- Not recorded: the ISO check date for G1. My message was cut off before the date, so it never reached the AI and the notes keep a placeholder.
